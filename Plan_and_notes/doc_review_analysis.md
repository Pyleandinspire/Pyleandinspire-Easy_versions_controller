# PLAN.md vs processes.md 对比分析报告

> 生成日期: 2026-06-03

---

## 一、致命冲突 (Blocker)

### 1.1 git2dart 技术方案不可行

| 文档 | 原文 | 问题 |
|------|------|------|
| PLAN.md | "把git集成到软件里面，基础功能打开即用（内置Git程序）"、"使用git2dart库进行Git操作" | 假设git2dart可跨平台运行 |
| processes.md | 步骤 1.2, 2.1.3, 2.6.4, 2.7.1, 2.7.3, 2.7.6, 3.3 等大量引用 git2dart | 全部基于git2dart设计 |

**实测结果**: git2dart 在 Windows 上无法运行：
- `libgit2.dll` 缺少 OpenSSL 依赖（libcrypto-1_1-x64.dll 不存在）
- `libssh2.dll` 无法加载（错误代码126）
- `Isolate.resolvePackageUriSync` 在编译后的 Flutter 应用中无法解析包位置
- macOS/Linux 未测试但预期存在类似问题

**结论**: processes.md 中所有涉及 git2dart 的步骤（约 10+ 个步骤）需要重写，改用纯 Dart + SQLite 方案。

### 1.2 "内置Git程序" 概念不准确

| 文档 | 原文 | 问题 |
|------|------|------|
| PLAN.md | "内置Git程序" | 暗示完整 Git 功能（分支、合并、远程等） |
| 实际 | git2dart 只是 libgit2 的 Dart FFI 绑定 | 功能有限，且不包含 git.exe |

**建议**: 修正为"内置版本控制引擎"，不再使用 Git 术语。

## 二、概念矛盾 (Contradiction)

### 2.1 数据存储路径不可行

| 文档 | 原文 | 问题 |
|------|------|------|
| PLAN.md | "数据都存储在软件本地（软件安装目录下）" | 安装目录通常需要管理员权限 |
| 实际 | 应用数据应存储在 `%APPDATA%` (Windows) / `~/Library/Application Support` (macOS) / `~/.local/share` (Linux) | 标准做法 |

**受影响步骤**: 2.1.3（Git 仓库初始化路径）

### 2.2 功能优先级排序矛盾

| 功能 | PLAN.md 优先级 | processes.md 实现顺序 | 矛盾 |
|------|---------------|---------------------|------|
| 设置页面 | P1（可延后） | 功能4（较早实现） | 顺序矛盾 |
| AI生成commit消息 | P0（MVP必须） | 功能8（靠后实现） | 优先级不匹配 |
| 自动保存状态指示器 | P0（MVP必须） | 步骤 2.6.5（功能6最后） | 依赖关系合理但文本描述矛盾 |

**建议**: 统一优先级排序，P0 功能应先实现。

### 2.3 "Git仓库" vs "版本快照" 术语不一致

- PLAN.md 全文使用 "Git仓库"、"commit"、"commit历史" 等术语
- 如果改用纯Dart方案，需统一替换为"版本快照"、"版本记录"、"版本历史"

## 三、不合理之处 (Unreasonable)

### 3.1 步骤 2.7.3 diff 算法选择不合理

| 当前 | 问题 |
|------|------|
| "使用自实现的LCS算法，后续可优化为Myers diff算法" | LCS 复杂度 O(n*m)，Myers diff 才是标准 diff 算法 |
| | 应该直接用 Myers diff，而不是先 LCS 再优化 |

**建议**: 直接实现 Myers diff 算法。

### 3.2 步骤 2.7.0 编号不规范

- 步骤编号从 2.7.0 开始，其他功能从 x.1 开始
- 建议统一为 2.7.1，后续步骤顺延

### 3.3 步骤 2.11.1 PDF 预览依赖不明确

| 文档 | 原文 | 问题 |
|------|------|------|
| PLAN.md | "集成 pdfx 库" | pdfx 在 Flutter 生态中不稳定，跨平台兼容性差 |
| | | 未说明各平台是否需要额外配置 |

**建议**: 明确 pdfx 各平台配置要求，或改用 WebView 方案。

### 3.4 步骤 2.11.3 PPTX 功能描述冗余

- 步骤 2.11.3 标题是"实现 PPTX 预览"，但内容说"当前方案：使用系统默认程序打开"
- 既然没有实际实现，不应该作为一个独立步骤

### 3.5 步骤 3.2 性能测试指标不切实际

| 指标 | 问题 |
|------|------|
| "大文件处理响应迅速（不超过5秒加载）" | 100MB 文件在 5 秒内加载不现实 |
| "长时间运行无内存泄漏（24小时）" | 24小时稳定性测试对 MVP 阶段过于严格 |
| "diff 算法对中等大小文件（1000行以内）响应迅速" | 未定义"迅速"的具体指标 |

## 四、遗漏与缺失 (Missing)

### 4.1 缺少错误处理步骤

- 整个 processes.md 没有独立的错误处理设计步骤
- 所有步骤的测试要求都假设"正常情况"
- 应增加"全局错误处理机制"步骤

### 4.2 缺少步骤间依赖关系图

- 部分步骤有依赖关系但未明确说明
- 例如：步骤 2.6.4 依赖 2.1.3，但 2.1.3 如果失败（git2dart不可用），2.6.4 无法进行

### 4.3 缺少数据库迁移步骤

- 如果从 git2dart 方案切换到纯 Dart 方案，数据库 schema 需要变更
- 没有考虑数据库版本升级机制

### 4.4 缺少平台特定配置说明

- 未说明各平台需要的额外配置（如 macOS 的 entitlements、Windows 的注册表等）
