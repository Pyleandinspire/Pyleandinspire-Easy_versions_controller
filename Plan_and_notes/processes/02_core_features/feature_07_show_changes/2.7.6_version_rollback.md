# 步骤 2.7.6 实现版本回退功能

**所属功能**: 功能7 - 展示更改

**目标**: 用户可以将文件回退到任意历史快照版本

**回退原理**:

- 从快照目录读取选中版本的快照文件
- 将该快照文件内容复制覆盖当前原始文件
- 回退操作本身也创建一个新快照（记录为"回退到 XX 版本"）

**要做什么**:

- 从 snapshots 表中读取选中快照的元数据
- 根据 `snapshot_path` 读取快照文件内容
- 展示回退确认弹窗，显示目标版本信息（时间、描述）
- 用户确认后：
  1. 先将回退前的最新文件状态保存为一个新快照（标记为"回退前自动保存"）
  2. 将选中快照文件内容复制覆盖原始文件
  3. 在 snapshots 表中插入一条新记录（message = "回退到版本 {timestamp}"）
- AI 自动解释回退影响（可选）

**回退流程**:

```
用户选择历史快照 → 确认弹窗 →
  → 保存当前文件为新快照（防丢失）→
  → 复制快照内容覆盖原文件 →
  → 写入新快照记录 → 刷新界面
```

> ⚠️ **重要变更**: 不再使用 git2dart 的 reset/revert 操作。改为直接文件复制覆盖方式，
> 逻辑简单透明，不依赖任何外部库。

**测试要求**:

- ✅ 能正确回退到任意历史快照版本
- ✅ 回退后文件内容与目标快照完全一致
- ✅ 回退前自动保存当前版本（安全保护）
- ✅ 回退操作创建新的快照记录
- ✅ 回退前有确认弹窗
- ✅ 回退后界面正确刷新
