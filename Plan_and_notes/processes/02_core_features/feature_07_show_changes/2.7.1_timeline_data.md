# 步骤 2.7.1 实现时间轴数据读取

**所属功能**: 功能7 - 展示更改

**目标**: 从数据库读取版本快照历史，并实现缓存优化提升响应速度

**要做什么**:

- 从 snapshots 表中读取指定文件的所有快照记录
- 关联 tracked_files 表获取文件信息
- 按时间戳倒序排列（最新在前）
- 返回快照列表（时间戳、版本描述、文件大小、哈希值）
- 支持分页加载（避免一次加载过多快照）
- **缓存优化**: 使用 Provider 的 `keepAlive` 和手动缓存机制避免重复查询
  - 缓存策略：按 fileId 缓存快照列表
  - 缓存更新：创建新快照时更新对应 fileId 的缓存
  - 缓存失效：删除文件时清理对应缓存

**数据库查询**:

```sql
SELECT * FROM snapshots
WHERE file_id = ?
ORDER BY timestamp DESC
```

> ⚠️ **重要变更**: 不再从 git2dart 读取 commit 历史。快照数据存储在 snapshots 表中，
> 实际文件存放在 `snapshots/{file_uuid}/` 目录下。数据库只存元数据，文件内容直接从快照文件读取。

**缓存机制**:

| 缓存项 | 存储方式 | 更新时机 | 失效时机 |
|--------|----------|----------|----------|
| 快照列表 | Map<String, List<Snapshot>> | 查询成功后 | 文件删除时 |
| 当前文件内容 | Provider 状态 | 文件切换时 | 文件切换时 |
| 快照文件内容 | 临时缓存 | 快照预览时 | 预览关闭时 |

**测试要求**:

- ✅ 能正确读取指定文件的快照历史
- ✅ 时间戳倒序排列正确
- ✅ 快照数量与目录中实际文件数一致
- ✅ 无快照时返回空列表（不报错）
- ✅ 分页加载正常
- ✅ 缓存机制有效，重复切换文件时查询次数减少
- ✅ 缓存更新及时，新建快照后时间轴立即更新
