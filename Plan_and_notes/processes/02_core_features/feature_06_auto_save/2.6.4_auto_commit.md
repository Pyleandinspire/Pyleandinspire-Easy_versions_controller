# 步骤 2.6.4 实现版本自动保存

**所属功能**: 功能6 - 自动保存

**目标**: 将文件变更保存为新的版本快照

**核心思路**:

- 每次保存触发时，将当前文件复制一份到快照目录
- 快照文件按时间戳命名，保留原始文件名
- 通过 SHA-256 哈希判断内容是否真的变化，无变化则跳过
- 数据库只记录快照元数据，不存储文件内容

**要做什么**:

- 读取当前文件内容，计算 SHA-256 哈希值
- 与最新快照的哈希值比对：
  - 哈希值相同 → 内容无变化，跳过保存
  - 哈希值不同 → 有变化，创建新快照
- 复制文件到 `snapshots/{file_uuid}/` 目录下
  - 命名格式：`{yyyyMMdd_HHmmss}_{原始文件名}`
- 在 snapshots 表中插入一条元数据记录
- 默认使用 AI 生成消息，无 AI 时使用默认消息模板（如"自动保存"）
- 处理保存失败的情况（磁盘空间不足、权限不足等 → 记录错误日志）

**保存流程**:

```
文件变更事件 → 计时器到期 → 读取文件 → 计算哈希
  → 与最新快照比对 → 有变化？
    → 是：复制文件到快照目录 → 写入数据库 → 完成
    → 否：跳过，不创建重复快照
```

> ⚠️ **重要变更**: 不再使用 git2dart 或 SQLite BLOB 存储。改为直接文件复制方案——
> 简单、直观、大文件友好、跨平台零依赖。

**测试要求**:

- ✅ 文件变更后能正确创建新快照副本
- ✅ 快照文件内容与原文件完全一致
- ✅ 文件无变化时不会创建重复快照
- ✅ 快照元数据正确写入数据库
- ✅ 保存失败时有错误处理（不崩溃）
- ✅ 快照文件名格式正确
