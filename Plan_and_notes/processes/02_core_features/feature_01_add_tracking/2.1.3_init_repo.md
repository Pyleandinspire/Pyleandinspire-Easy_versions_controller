# 步骤 2.1.3 实现文件版本快照存储初始化

**所属功能**: 功能1 - 添加版本追踪

**目标**: 为每个追踪文件创建版本快照存储结构

**核心思路**:

- 每一次保存（自动/手动触发），复制一份当前文件的完整副本到快照目录
- 快照文件按时间戳命名，直观可读
- 用户选择某个快照 → 用该快照副本覆盖当前文件 → 即完成版本回退
- 简单、直观、跨平台、零依赖

**要做什么**:

- 在应用数据目录下创建 `snapshots/` 根目录
- 为每个追踪文件创建独立的快照子目录，如 `snapshots/{uuid}/`
- 添加文件时，立即创建第一个快照副本（初始版本）
- 快照文件命名规则：`{yyyyMMdd_HHmmss}_{原始文件名}`
  - 例：`20260603_201500_我的文档.txt`
- 在数据库中记录快照信息（路径、时间戳、文件大小、SHA-256 哈希值）
- 后续每次自动/手动保存时，复制新快照到该目录即可

**存储结构示例**:

```
{app_data_dir}/
└── snapshots/
    └── {uuid_1}/                        # 文件1的快照目录
        ├── 20260603_120000_doc.txt      # 第1个快照
        ├── 20260603_120500_doc.txt      # 第2个快照
        └── 20260603_121000_doc.txt      # 第3个快照
    └── {uuid_2}/                        # 文件2的快照目录
        └── 20260603_130000_notes.md     # 第1个快照
```

> ⚠️ **重要变更**: 原方案基于 git2dart / SQLite BLOB 存储快照。现已改为**文件副本**方案 —
> 直接将文件复制到快照目录，不存入数据库。数据库只存元数据（路径、时间、哈希、大小）。
> 优点：简单直观、大文件友好、用户可直接访问快照文件、零二进制依赖。

**数据库 snapshots 表结构**:
| 字段 | 类型 | 说明 |
|------|------|------|
| id | TEXT | 快照 UUID |
| file_id | TEXT | 关联的追踪文件 UUID |
| snapshot_path | TEXT | 快照文件的绝对路径 |
| timestamp | TEXT | 创建时间 (ISO 8601) |
| file_size | INTEGER | 文件大小（字节） |
| sha256_hash | TEXT | 文件内容 SHA-256 哈希值 |
| message | TEXT | 版本描述（AI生成或默认） |

**测试要求**:

- ✅ 快照根目录正确创建在应用数据目录下
- ✅ 每个追踪文件有独立的快照子目录
- ✅ 添加文件时初始快照文件被正确复制
- ✅ 快照文件名格式正确（时间戳 + 原名）
- ✅ 数据库正确记录了快照元数据
- ✅ 快照文件内容与原文件完全一致
