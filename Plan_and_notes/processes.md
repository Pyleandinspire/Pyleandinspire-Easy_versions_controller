### 功能 1：添加版本追踪

#### 步骤 2.1.1 实现文件选择对话框
**目标**：用户可以选择要追踪的文件
**要做什么**：
- 调用系统文件选择对话框
- 支持多选文件
- 不限制文件类型和大小

**测试要求**：
- ✅ 可以弹出文件选择对话框
- ✅ 可以选择一个或多个文件（任意类型和大小）
- ✅ 可以显示已选择的文件列表

---

#### 步骤 2.1.2 实现文件打标记和本地数据存储
**目标**：对选中的文件进行版本追踪管理
**要做什么**：
- 为每个文件创建唯一标识符（可基于文件路径或内容哈希）
- 在软件安装目录下创建数据存储目录
- 为每个文件单独创建对应的 Git 仓库（位于软件安装目录下）
- 存储文件元数据（路径、创建时间、最后访问时间等）

**测试要求**：
- ✅ 文件元数据可以正确保存到本地存储
- ✅ 同一文件再次添加时能够识别
- ✅ 可以在数据库中查询到已添加的文件
- ✅ 每个文件有独立的Git仓库
- ✅ Git仓库位于软件安装目录下

---

#### 步骤 2.1.3 实现文件扫描和定位机制
**目标**：处理文件找不到的情况
**要做什么**：
- 当文件找不到时，进行全盘扫描
- 默认扫描3分钟超时
- 扫描失败时，弹出错误提示对话框
- 提供"放弃追踪"和"提供路径"两个选项
- 不需要显示进度条

**测试要求**：
- ✅ 文件被移动后，软件能检测到找不到
- ✅ 能触发全盘扫描机制
- ✅ 扫描3分钟后超时
- ✅ 扫描失败后弹出正确的错误提示
- ✅ "放弃追踪"能从列表中移除该文件
- ✅ "提供路径"能重新关联到正确位置

### 功能 5：自动保存

#### 步骤 2.5.1 实现文件系统事件监听
**目标**：监听文件变更事件
**要做什么**：
- 使用 fs.watch 或 chokidar 等库监听文件变更
- 过滤掉不必要的事件（如临时文件变化）
- 记录最后一次修改的时间戳

**测试要求**：
- ✅ 修改文件能被检测到
- ✅ 频繁修改不会产生过多事件
- ✅ 删除和重命名文件也能正确响应

---

#### 步骤 2.5.2 实现用户中断操作检测和延迟提交
**目标**：用户停止编辑10秒后自动提交，且每3分钟强制保存一次（如果有修改）
**要做什么**：
- 实现双计时器逻辑：
  - 短计时器：用户中断操作后10秒提交
  - 长计时器：每3分钟检查一次，如果有修改则提交
- 每次文件变更重置短计时器
- 计时器超时后触发 Git 提交
- 支持用户自定义延迟时间（从设置读取）

**测试要求**：
- ✅ 修改文件后开始10秒倒计时
- ✅ 连续修改会重置10秒计时器
- ✅ 10秒倒计时结束后能触发提交
- ✅ 每3分钟检查一次，如果有修改则提交
- ✅ 3分钟内无修改不触发提交
- ✅ 自定义时间设置生效

---

#### 步骤 2.5.3 集成 Git 和实现自动提交
**目标**：将文件变更提交到 Git 仓库
**要做什么**：
- 使用内置Git程序
- 使用 libgit2 或 simple-git 等 Git 库
- 实现 git add
- 实现 git commit（默认使用 AI 生成消息，无 AI 时使用默认消息）
- 处理提交失败的情况

**测试要求**：
- ✅ Git 仓库能正确初始化
- ✅ 文件变更能正确添加到暂存区
- ✅ 能成功创建 commit
- ✅ commit 历史可以查看
- ✅ 所有修改都会保存版本
