# 19 - PLAN.md 与 processes.md 交叉检查报告

**日期**：2026-06-02
**目的**：对比 PLAN.md 和 processes.md，找出冲突、不合理和可改进之处

---

## 一、文档之间的冲突

### 1. 文件选择对话框设计冲突
- **PLAN.md** 第2节描述的是一个**自定义模态对话框**：有"文件列表、文件名/大小/修改日期、过滤选项（全部/文档/图片/其他）"
- **processes.md** 步骤 2.1.1 写的是"使用 file_picker 库调用**系统文件选择对话框**"
- **冲突**：PLAN.md 想要自定义 UI，processes.md 用的是系统原生对话框。两者完全不同
- **建议**：统一为系统原生对话框（file_picker），自定义对话框开发成本高且体验不一定比原生好

### 2. "输入/输出"格式描述含糊
- **PLAN.md** 写的是"展示格式/输出格式：时间 + 更改概括 + **图片**"
- **两份文档的详细 UI 描述**中，时间轴每条记录都是"时间戳 + 更改摘要 + commit图标"，**没有任何地方提到图片**
- **冲突**："图片"这个输出要求与所有详细设计矛盾
- **建议**：删除"图片"，改为"时间 + 更改概括 + 版本标识"

### 3. AI 对话面板形式冲突
- **PLAN.md** 第9节和 **processes.md** 步骤 2.8.2 都写的是"**右侧滑出面板**"
- **实际代码**实现的是独立页面（`ai_agent_view.dart`）
- **冲突**：文档描述与实际实现不一致
- **建议**：根据三栏布局的实际情况，AI 对话作为右侧滑出面板会遮挡时间轴，建议改为：1）在中间预览区内以抽屉形式弹出，或 2）保持独立页面但通过顶部按钮触发

### 4. processes.md 内部库名不一致
- 步骤 1.2 已更新为 `watcher`
- 步骤 2.5.1 仍写的是"使用 **file_watcher** 库监听文件变更"
- **建议**：统一为 `watcher`

## 二、不合理的地方

### 5. DOCX 编辑过于理想化
- **processes.md** 步骤 2.9.6 写"集成 docx 库解析 DOCX → 转换为富文本 → 编辑 → 保存为 DOCX"
- **现实**：Flutter 生态中**没有成熟的 DOCX 编辑库**。`docx` 库只能生成简单文档，无法完整解析和还原 DOCX 的复杂格式（表格、图片、样式等）
- **建议**：降级为"DOCX 只读预览"，或使用系统默认程序打开 DOCX 文件

### 6. PPTX 预览缺乏库支持
- **processes.md** 步骤 2.10.3 写"集成 pptx 库解析 PPTX 文件"
- **现实**：Flutter 生态中**没有可用的 PPTX 解析库**，`pptx` 这个包不存在或极不成熟
- **建议**：PPTX 预览标记为"远期目标"或"使用系统默认程序打开"

### 7. Excel 预览功能过于复杂
- **processes.md** 步骤 2.10.2 要求"保留原表格格式（颜色、边框、对齐）"
- **现实**：`excel` 库可以解析数据，但**还原完整格式非常困难**
- **建议**：简化为"显示表格数据，支持工作表切换"，不要求完全还原格式

### 8. 代码折叠功能不合理
- **PLAN.md** 第10节写"代码折叠（支持函数/类级别）"
- **processes.md** 中**完全没有对应的实现步骤**
- **现实**：代码折叠需要语法解析器，flutter_highlight 只做高亮不做解析，实现成本极高
- **建议**：从 PLAN.md 中删除代码折叠，或标记为远期目标

### 9. 全盘扫描 3 分钟超时可能不够
- **PLAN.md** 和 **processes.md** 都写"默认3分钟超时"
- **现实**：现代硬盘容量动辄 500GB-2TB，3 分钟全盘扫描可能连目录都遍历不完
- **建议**：改为"智能扫描"——先扫描常见目录（桌面、文档、下载），再扩展到全盘，超时改为 5 分钟或可配置

## 三、可以改进的地方

### 10. 缺少"中间文件预览区"的实现步骤
- **PLAN.md** 已更新为三栏布局，新增了"中间面板 - 文件预览区"的描述
- **processes.md** 中**没有对应的步骤**来描述中间预览区的实现
- **建议**：在功能6（展示更改）之前或之中，新增步骤"2.6.0 实现中间文件预览面板"

### 11. 缺少"文件列表搜索"的实现步骤
- **PLAN.md** 第1节左侧面板描述了"搜索框"
- **processes.md** 步骤 2.2.1 **没有提到搜索功能**
- **建议**：在步骤 2.2.1 中补充搜索框的实现

### 12. 缺少"顶部导航栏 AI 助手按钮"的实现步骤
- **PLAN.md** 第1节顶部导航栏包含"AI助手按钮"
- **processes.md** 中**没有步骤**描述在顶部导航栏添加此按钮
- **建议**：在步骤 2.8.2 中补充"在顶部导航栏添加 AI 助手入口按钮"

### 13. processes.md 步骤 3.3 测试要求遗漏
- 步骤 3.3 测试要求中仍写着"git.dart 库在各平台正常工作"，但步骤正文已更新为 git2dart
- **建议**：统一测试要求中的库名

### 14. PLAN.md 技术实现要点不完整
- 只列了 `flutter_quill`、`flutter_markdown`、`pdfx` 三个 UI 组件库
- 缺少 `flutter_highlight`（语法高亮）、`excel`（Excel解析）、`archive`（数据导出压缩）
- **建议**：补充实际需要用到的库列表

### 15. 功能优先级没有标注
- 两份文档都没有标注哪些功能是 MVP（最小可行产品）必须的，哪些是后续版本可以加的
- DOCX 编辑、PPTX 预览、代码折叠等高难度功能与核心功能混在一起
- **建议**：将功能分为 P0（MVP 必须）、P1（重要但可延后）、P2（远期目标）三级

### 16. 缺少"版本回退"步骤
- **PLAN.md** 功能6提到"选择版本"，暗示用户可以回退到某个历史版本
- **processes.md** 中**没有步骤**描述如何实现版本回退（checkout 某个历史版本的文件内容覆盖当前文件）
- **建议**：在功能6中新增步骤"实现版本回退操作"
